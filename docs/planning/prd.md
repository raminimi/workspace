# PRD: 월세 자동이체 연계 '원스탑 월세 세제혜택 케어' (MVP)

> **문서 성격**: 본 PRD는 `docs/planning/rent-tax-benefit-concept.md`(서비스 컨셉·5단계 UX 플로우 초안)와 `docs/planning/business-model.md`(사업성 검토)를 근거로 작성되었습니다. 파이프라인상 앞 단계인 `docs/planning/market-research.md`(시장조사)는 아직 존재하지 않습니다 — 즉 이 PRD는 정식 시장조사 없이, 컨셉 문서와 사업성 검토에 명시된 **미검증 가정**(전환율 30%, 해지 방어 3~5%p, 크로스셀 전환율 5% 등은 모두 근거 없는 추정치임)을 그대로 이어받아 진행합니다. 시장조사가 뒤늦게 진행될 경우 본 문서의 목표 수치와 성공 지표 임계값은 재검토가 필요합니다.

**요약**: 이 서비스는 월세 자동이체 설정을 트리거로 세액공제/현금영수증 자격을 자동 판정하고 연말정산 서류를 자동 적립·발급해주는 기능이다. 사업성 검토 결과 독자적인 직접 수익원이 없고 "월세 자동이체 상품의 무료 부가 리텐션·크로스셀 도구"로 성격이 재정의되었으므로, 본 PRD는 컨셉 문서의 5단계 풀 플로우(트리거 → 스크래핑 조회 → 계약서 OCR → 결과/신청 → 연말정산 사후관리)를 한 번에 구축하지 않는다. 대신 **가장 적은 투자로 리텐션(해지 방어)과 크로스셀 전환 가설을 실측 검증**할 수 있는 최소 범위 — 마이데이터 기반 자격 자동 판정, 월별 증빙 자동 적립, 연말정산 PDF 발급, 크로스셀 넛지와 계측 인프라 — 로 MVP를 좁히고, 계약서 OCR·국세청 민원 자동 대행·청약 락인 기능 등은 MVP 성과 검증 후 재결정하는 확장 로드맵(Won't-have for now)으로 명확히 분리한다.

## 0. 핵심 가정 (시장조사 부재에 따른 전제)

- 시장조사 문서 부재로, 아래 수치는 모두 `business-model.md`에 명시된 **검증되지 않은 가정**이며 MVP 실측을 통해 대체되어야 한다.
  - 자동이체 신규 고객 중 기능 완주율(자격조회~PDF 발급) 30% 내외
  - 이용 고객의 자동이체 계좌 유지율 개선 효과 3~5%p (근거 없음, MVP 목적 자체가 이 수치를 실측하는 것)
  - 크로스셀(청약통장/전월세대출) 전환율 이용 고객의 5% 내외
- 사업성 검토의 결론(직접 수익원 없음, 무료 부가서비스, 크로스셀 재무 기여는 낮게 잡을 것)을 그대로 수용하고, 본 PRD는 **매출이 아니라 리텐션·크로스셀·데이터 파이프라인 안정성 검증**을 목표로 한다.

## 1. 배경 및 목표

### 배경
- 월세 세입자는 세액공제/현금영수증 중 유리한 쪽을 스스로 판단하기 어렵고, 매달 이체확인증을 모으는 번거로움과 연말정산 시즌 서류 몰림, 집주인과의 관계 악화 우려로 신청 자체를 포기하는 경우가 많다 (컨셉 문서 3장).
- 국세청 연말정산 간소화 서비스는 아직 월세 세액공제 관련 서류(계약서, 이체내역, 등본)를 자동 수집하지 않아 이 갭이 현재는 유효하지만, 향후 정부가 이 영역을 자동화하면 서비스의 존재 이유가 잠식될 수 있다 (`business-model.md` 3.1, 5.1).
- 사업성 검토 결과 이 기능에는 독자 수익원이 없으므로, 대규모 선투자로 컨셉 문서의 5단계 풀 플로우를 한 번에 구축하는 것은 리스크가 크다. 소규모 MVP로 핵심 가설(리텐션 방어 효과, 크로스셀 전환)을 먼저 실측 검증해야 한다는 것이 명시적 권고다 (`business-model.md` 5.3, 6장).

### 목표 (측정 가능)
1. **리텐션 가설 검증**: 이 기능을 완주(자격 판정 + PDF 발급)한 고객군과 미이용 고객군의 월세 자동이체 계좌 해지율 차이를 실측 데이터로 확보한다. (MVP 출시 후 6개월 시점 중간 측정, 12개월 시점 확정 측정)
2. **크로스셀 가설 검증**: PDF 발급 완료 시점 넛지 노출 → 청약통장/전월세대출 상품 페이지 클릭 → 실제 신규 가입까지 이어지는 퍼널 전환율을 실측한다.
3. **비용 구조 검증**: 스크래핑 성공률/오류율을 측정해, 향후 규제 변화(유상 API 전환 등) 시 원가에 미치는 영향을 조기에 가늠할 수 있는 베이스라인을 확보한다.
4. 위 세 가지 실측 데이터를 근거로, 2단계(계약서 OCR, 국세청 민원 자동 대행, 청약 락인 기능 등) 투자 여부를 재결정한다.

**본 서비스는 매출 목표를 갖지 않는다.** 성공/실패는 5장(성공 지표)의 리텐션·크로스셀·운영 지표로만 판단한다.

## 3. 기능 요구사항 (MoSCoW)

### MVP 판단 근거
컨셉 문서의 Step1~5 중, **리텐션·크로스셀 가설을 검증하는 데 필수적인 최소 경로**는 "① 자동이체 트리거 넛지 → ② 마이데이터 기반 자격 자동 판정 → ③ 월별 증빙 자동 적립 → ④ 연말정산 PDF 발급 → ⑤ 이 발급 시점의 크로스셀 넛지"이다. 이 경로가 없으면 애초에 측정할 "이용 고객" 코호트 자체가 생기지 않는다. 반면 **계약서 OCR(Step3)과 국세청 현금영수증 자동 신청 대행(Step4 Case B의 자동화 부분)은 가설 검증에 필수가 아니면서 리스크/비용이 큰 항목**이므로 MVP에서 제외한다.
- 계약서 OCR 제외 근거: 자동이체 설정 시 이미 임차 주소·임대인 정보·월세 금액이 시스템에 존재하므로, 등본 스크래핑 주소와 자동이체 등록 주소를 대조하는 것만으로 1차 판정이 가능하다. OCR은 정확도를 높이는 부가 기능(오인식 리스크가 크고 구축비가 큼, `business-model.md` 4.1)이지 판정 자체의 필수조건이 아니다.
- 국세청 현금영수증 자동 신청 대행 제외 근거: `business-model.md` 2.1에서 지적한 세무대리 유사행위 규제 리스크가 가장 큰 항목이며, 5.3에서도 "규제 민감도가 높은 기능은 법무/컴플라이언스 검토 후 2단계에서 붙일 것"을 명시적으로 권고했다. MVP에서는 자동 대행 대신 **신청 방법 안내 + 홈택스 딥링크**로 대체해 규제 노출을 최소화한다.
- 계측(F9) 인프라는 화면 기능은 아니지만, 애초에 이 MVP의 존재 목적이 "가설 검증"이므로 최우선 Must로 분류한다.

| F18 | 광고/제휴 리베이트 연계 (부동산 중개, 보증보험 등) | `business-model.md` 수익원 후보 C | **Won't (이번 MVP 제외)** | 개인정보 목적외 이용 이슈로 채택 보류 |

### 기능 간 의존관계 요약 (UX 플로우 설계 참고용)
- F9(계측)는 F1 출시 이전에 선행 구축되어야 하며, 이후 모든 기능은 계측 이벤트를 발생시켜야 한다.
- F2(자격 판정)가 실패/거부되면 F3·F7으로 분기하지 않고 F10·F11의 예외 경로로 빠진다.
- F3(Case A) → F4(월별 적립) → F5(PDF 발급) → F8(크로스셀 넛지)은 세액공제 트랙의 단일 선형 흐름이다.
- F7(Case B)은 MVP에서 F4/F5로 이어지지 않는다(자동 적립 대상은 세액공제 트랙만). 현금영수증 트랙 사용자의 연말정산 자료는 국세청 간소화 서비스가 익년부터 자동 반영하므로 본 서비스가 추가로 서류를 적립할 필요가 없다(컨셉 문서/사업성 검토 근거).
- F8은 F2(무주택 인증 성립 시점)와 F5(PDF 발급 시점) 두 지점에서 각각 노출 가능하되, MVP에서는 이탈 최소화를 위해 F5 시점 1회 노출을 기본으로 하고 F2 시점 노출은 A/B 테스트 대상으로 둔다.

## 5. 범위 / 비범위

### 이번 MVP 범위 (Must + Should = F1~F12)
- 자동이체 트리거 넛지, 마이데이터 기반 자격 자동 판정(등본+소득+주택 기준시가 API, OCR 없음), 세액공제 트랙의 월별 증빙 자동 적립과 연말정산 PDF 발급, 현금영수증 트랙 안내(자동 대행 없음), 크로스셀 넛지 노출 및 클릭 트래킹, 예외처리(스크래핑 실패/동의 철회/불확실 판정), 전 구간 계측 인프라.

### 이번 버전 비범위 (Won't-have, 확장 로드맵으로 분리 — F13~F18)
| 항목 | 제외 사유 | 재검토 조건 |

## 6. 성공 지표

### North Star Metric
**"이용 고객군 대비 미이용 고객군의 월세 자동이체 계좌 해지율 격차(%p, 리텐션 방어 효과)"**
- 정의: F3(세액공제 케어 시작) 완주 고객 코호트 vs 자격 판정만 하고 이탈했거나 F1 넛지를 아예 클릭하지 않은 대조군의, 3개월/6개월/12개월 시점 자동이체 계좌 유지율 비교.
- 근거: 사업성 검토가 이 서비스의 존재 이유를 "리텐션 도구"로 재정의했으므로, 매출이 아니라 이 지표가 확장 투자 여부를 결정하는 핵심 근거가 되어야 한다.
- MVP 단계 목표: 3개월/6개월 시점에 통계적으로 유의미한 방향성(양의 격차)이 관측되는지 확인 — `business-model.md`의 가정치(3~5%p)는 검증 대상이지 목표치가 아니다.

### 보조 지표
| 지표 | 정의 | 목적 |
| --- | --- | --- |
| 크로스셀 클릭 전환율 | F8 넛지 노출 대비 클릭 비율 | 크로스셀 가설의 상위 퍼널 검증 |
| 크로스셀 가입 전환율 | F8 클릭 대비 실제 상품(청약통장/전월세대출) 신규 가입 비율 | 크로스셀 가설의 최종 검증, 재무 기여 규모 산정 |

### 측정 방법 및 기간
- F9(계측 인프라)로 전 구간 이벤트를 코호트 태깅하여 수집한다.
- North Star는 최소 6개월(중간), 12개월(확정) 관측 기간이 필요하므로, MVP 출시 후 최소 2분기 이상 데이터가 쌓이기 전에는 확장 투자를 결정하지 않는다.
- 계절성(연말정산은 1~2월 집중)을 감안해, 코호트는 출시 후 최소 1회 연말정산 시즌(F5 발급 시점)을 포함하도록 설계한다.
